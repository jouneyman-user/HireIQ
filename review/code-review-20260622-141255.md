## Summary

Found **4 major bugs** that block Issue #5 from being implemented. The first two are hard blockers — the frontend cannot display questions because the generation pipeline is completely broken between the UI and backend. The remaining two are missing UI components that the issue explicitly requires.

---

## 🔴 Bug 1 — Frontend ↔ Backend contract mismatch on `POST /generate/`  (BLOCKER for #5)

**Severity:** Critical — every generation call from the UI fails with 422.

**Evidence:**

- `frontend/src/App.tsx` (lines ~41–46) sends:
  ```ts
  body: JSON.stringify({
    resume_id: activeResumeId,       // ❌ backend expects resume_text
    job_title: roleData.jobTitle,
    seniority_level: roleData.seniorityLevel,
    key_skills: roleData.keySkills,
  })
  ```

- `backend/app/routers/generate.py` `GenerateRequest` requires:
  ```python
  class GenerateRequest(BaseModel):
      resume_text: str               # ✅ expects the actual text
      job_title: str
      seniority_level: str
      key_skills: list[str]
  ```

- `frontend/src/App.tsx` (lines ~13–19) defines an **incorrect response type**:
  ```ts
  type GenerateResult = {
    message: string                  // ❌ backend returns categorised questions
    resume_id: number
    job_title: string
    seniority_level: string
    key_skills: string[]
  }
  ```

- `backend/app/routers/generate.py` returns:
  ```python
  class GenerateResponse(BaseModel):
      technical: list[Question]      # ✅ actual response shape
      behavioural: list[Question]
      culture_fit: list[Question]
  ```

**Impact:** The UI sends `resume_id` (a number); backend validates `resume_text` (a required string) and returns 422. The "Generate" button is effectively broken. Even if it succeeded, the frontend type expects `{ message, resume_id, ... }` but the backend returns `{ technical, behavioural, culture_fit }` — the questions would be silently dropped.

**Fix direction:**
1. Make the frontend send `resume_text` instead of `resume_id` (see Bug 3 for how to obtain it).
2. Update `GenerateResult` type in `App.tsx` to match `GenerateResponse`:
   ```ts
   type Question = {
     text: string
     follow_up: string
     what_to_listen_for: string
   }
   type GenerateResult = {
     technical: Question[]
     behavioural: Question[]
     culture_fit: Question[]
   }
   ```

## 🔴 Bug 2 — No question display UI component exists  (BLOCKER for #5)

**Severity:** Critical — the issue requires a full question display UI but no such component exists.

**Evidence:**

- `frontend/src/App.tsx` (lines ~73–74) renders the generation result as a plain paragraph:
  ```tsx
  {generateResult && <p style={{ color: 'green' }}>{generateResult.message}</p>}
  ```
- No `QuestionDisplay`, `QuestionCard`, `CategorySection`, or similar component exists in `frontend/src/components/`.
- The issue acceptance criteria require:
  - [ ] Collapsible category sections (Technical, Behavioural, Culture Fit)
  - [ ] Each question card shows main question, follow-up, and evaluation tip
  - [ ] Loading skeleton while generation is in progress
  - [ ] Copy-to-clipboard button on individual questions and full set

**Impact:** Even if Bug 1 is fixed and the frontend receives the correct response, there is zero UI to display the questions. The 4 acceptance criteria items are all unimplemented.

**Fix direction:** Create a new `QuestionDisplay.tsx` component with:
1. `CategorySection` — collapsible accordion for each category (Technical, Behavioural, Culture Fit)
2. `QuestionCard` — displays `text`, `follow_up`, and `what_to_listen_for` (evaluation tip)
3. Loading skeleton placeholder shown when `generating` is true
4. Copy-to-clipboard buttons using `navigator.clipboard.writeText()`

## 🔴 Bug 3 — No resume text extraction or retrieval endpoint  (BLOCKER for #1)

**Severity:** Critical — without text extraction, the frontend cannot send `resume_text` to the backend.

**Evidence:**

- `backend/app/models/resume.py` — `Resume` model has no `extracted_text` column. Columns: `id, candidate_name, candidate_email, original_filename, stored_filename, content_type, file_size_bytes, uploaded_at`.
- `backend/app/routers/resumes.py` `upload_resume` only writes raw bytes to `uploads/resumes/<uuid>.<ext>`. No text extraction.
- `backend/requirements.txt` does **not** list `pypdf`, `pdfplumber`, `python-docx`, or any text-extraction library.
- No `GET /resumes/{id}/text` endpoint exists to retrieve extracted text.

**Impact:** The frontend has the resume file uploaded but has no way to get the text content to send to the generate endpoint. The entire generation pipeline is a dead end.

**Fix direction:**
1. Add `extracted_text = Column(Text, nullable=True)` to the `Resume` model.
2. Add a migration to create the new column.
3. Add `pypdf` and `python-docx` to `requirements.txt`.
4. Extract text synchronously inside `upload_resume` and store in `extracted_text`.
5. Add `GET /resumes/{resume_id}/text` endpoint (or include `extracted_text` in the existing `GET /resumes/{id}` response).
6. In the frontend, fetch the resume text before calling generate.

## 🟠 Bug 4 — Wrong API endpoint base path  (BLOCKER for #5)

**Severity:** High — the frontend calls `/api/generate/` but the backend serves at `/generate/`.

**Evidence:**

- `frontend/src/App.tsx` (line ~40):
  ```ts
  const res = await fetch('/api/generate/', { ... })
  ```

- `backend/app/main.py` — no `/api` prefix on any router:
  ```python
  app.include_router(generate.router)   # → /generate/
  ```

- `frontend/src/App.tsx` (line ~30):
  ```ts
  fetch('/api/resumes/')   // ❌ should be /resumes/
  ```

**Impact:** Every API call from the frontend returns 404 (or is intercepted by the Vite dev server proxy if configured). The API calls never reach the FastAPI backend.

**Fix direction:** Either:
1. Update the frontend to use `/generate/` and `/resumes/` (remove `/api/` prefix), or
2. Add a `prefix="/api"` to all router includes in `main.py`, or
3. Configure Vite proxy (`vite.config.ts`) to forward `/api/` to the backend.

2. **Fix Bug 4** (align API paths) — otherwise no API call reaches the backend.

4. **Implement Bug 2** (build `QuestionDisplay` component with all 4 acceptance criteria) — only after the pipeline works end-to-end.

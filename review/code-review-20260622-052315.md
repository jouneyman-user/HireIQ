# Code Review — Issue #7 (Role template library) blockers

- **Issue:** https://github.com/jouneyman-user/HireIQ/issues/7
- **Repo commit reviewed:** `dd28573604fced3bb98d30b093daeb534e5c0787`
- **Reviewer:** automated code review pass ahead of M3 / Issue #7 work
- **Scope:** `backend/app/**`, `frontend/src/**`, `backend/migrations/**`, `backend/requirements.txt`

## Summary

Found **8 major bugs**. The first two are hard blockers — the role-template library cannot land without them. The remaining six are quality/robustness bugs that should be fixed alongside the M3 work so the new feature ships on a stable foundation rather than inheriting the same 500s M2 already produces.

---

## 🔴 Bug 1 — Frontend ↔ Backend contract mismatch on `POST /generate/`  (BLOCKER for #7)

**Severity:** Critical — every generation call from the UI fails with 422.

**Evidence:**

- `frontend/src/App.tsx` (lines ~41–46) sends:
  ```ts
  body: JSON.stringify({
    resume_id: activeResumeId,
    job_title: roleData.jobTitle,
    seniority_level: roleData.seniorityLevel,
    key_skills: roleData.keySkills,
  })
  ```
- `backend/app/routers/generate.py` `GenerateRequest` requires:
  ```python
  class GenerateRequest(BaseModel):
      resume_text: str
      job_title: str
      seniority_level: str
      key_skills: list[str]
  ```

**Impact:** UI sends `resume_id`; backend validates `resume_text` and returns 422. The "Generate" button is effectively broken in the happy path.

**Fix direction:** Either (a) make the frontend send `resume_text` (after extraction — see Bug 2), or (b) make the backend accept `resume_id`, look the row up, and use the stored extracted text. Option (b) is preferable for #7 because role templates will want to reuse a resume without re-uploading.

---

## 🔴 Bug 2 — No resume-text extraction anywhere  (BLOCKER for #7)

**Severity:** Critical — without this, the entire generation pipeline has nothing to feed Claude.

**Evidence:**

- `backend/app/models/resume.py` — `Resume` has no `extracted_text` column. Columns: `id, candidate_name, candidate_email, original_filename, stored_filename, content_type, file_size_bytes, uploaded_at`.
- `backend/app/routers/resumes.py` `upload_resume` only writes raw bytes to `uploads/resumes/<uuid>.<ext>`. No text extraction step.
- `backend/requirements.txt` does **not** list `pypdf`, `pdfplumber`, `python-docx`, or any text-extraction library.

**Impact:** Even if Bug 1 is fixed and the frontend sends `resume_id`, the backend has no way to turn a PDF/DOCX into the `resume_text` Claude needs. A role template that "pre-fills the form" can save role fields, but it cannot kick off generation unless the resume row carries extractable text.

**Fix direction:**
1. Add `extracted_text = Column(Text, nullable=True)` to `Resume`.
2. Add a migration (extend `backend/migrations/init_db.py` or introduce Alembic).
3. Add `pypdf` and `python-docx` to `requirements.txt`.
4. Extract synchronously inside `upload_resume` (or in a background task) and store the result.
5. Surface extraction failures in the upload response so the UI can warn the recruiter.

## 🟠 Bug 3 — `claude_service` crashes on malformed Claude responses → HTTP 500

**Severity:** High — docstring promises 502; runtime delivers 500.

**Evidence:** `backend/app/services/claude_service.py`:

```python
raw_text = message.content[0].text   # IndexError if content == []
                                        # AttributeError if block is a refusal/tool_use
...
for category in _required_categories:
    ...
    if len(data[category]) < 3:       # TypeError if category is None / scalar / wrong type
```

The route later does `Question(**q)` for each item — no shape validation before that either, so a category containing a non-dict (e.g. a bare string) will raise `TypeError` inside `pydantic`.

**Impact:** When Claude returns a refusal, an empty content block, or a malformed JSON shape (all of which happen in production), the user sees a 500 instead of the documented 502, and the exception bubbles out of the route unhandled.

**Fix direction:**
- Guard `message.content` (handle refusal blocks, empty list).
- Validate each category with `isinstance(data[category], list)`.
- Validate each item's shape with `Question.model_validate(q)` before returning.

## 🟠 Bug 4 — Missing `ANTHROPIC_API_KEY` → HTTP 500 instead of 502

**Severity:** High.

**Evidence:** `backend/app/services/claude_service.py`:

```python
api_key = os.getenv("ANTHROPIC_API_KEY")
client = anthropic.Anthropic(api_key=api_key)   # raises if api_key is None
...
except anthropic.APIError as exc:               # does NOT catch the None-key error
```

`anthropic.Anthropic(api_key=None)` raises an error that is not an `APIError`, so the `try/except` block is bypassed and the route returns 500.

**Fix direction:** Either read the env var into a constant at module load and raise `ClaudeServiceError` if it's missing, or wrap the client construction in the `try/except APIError` block. Log a clear "ANTHROPIC_API_KEY not set" message.

## 🟡 Bug 5 — `upload_resume` is `async def` but uses synchronous SQLAlchemy

**Severity:** Medium — performance/correctness regression under load.

**Evidence:** `backend/app/routers/resumes.py` — `upload_resume` is `async def`, but the route calls `db.add / db.commit / db.refresh` on a regular `Session` and performs a synchronous `open(...).write(contents)`.

**Impact:** FastAPI runs `async def` handlers on the event loop. The blocking file write and sync DB calls stall the loop until the request finishes. With concurrent uploads (which a recruiter tool will see on first use), every other request stalls.

**Fix direction:** Drop `async` from the signature (FastAPI runs sync routes in a threadpool — perfectly fine here), or migrate to `AsyncSession` and `await file.write(...)`.

---

## 🟡 Bug 6 — Deprecated `declarative_base` import + CWD-relative DB path

**Severity:** Medium — runtime breakage on a future SQLAlchemy bump + data loss risk.

**Evidence:** `backend/app/database.py`:

```python
from sqlalchemy.ext.declarative import declarative_base  # removed in SQLAlchemy 3.x
...
DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./hireiq.db")
```

The project already pins `sqlalchemy>=2.0.0` in `requirements.txt`. The 3.x branch removed `sqlalchemy.ext.declarative` entirely. The default `sqlite:///./hireiq.db` is also CWD-relative, which is the exact "hireiq.db at repo root" red flag called out in `CODE_REVIEW.md`.

**Fix direction:**
```python
from sqlalchemy.orm import declarative_base
import pathlib
_DEFAULT_DB = pathlib.Path(__file__).parent / "hireiq.db"
DATABASE_URL = os.getenv("DATABASE_URL", f"sqlite:///{_DEFAULT_DB}")
```

## 🟡 Bug 7 — Hard-coded model identifier `claude-sonnet-4-5`

**Severity:** Medium.

**Evidence:** `backend/app/services/claude_service.py`:

```python
model="claude-sonnet-4-5",
```

No env var, no allow-list, no startup assertion.

**Impact:** If Anthropic renames or deprecates the model, every request 404s and the user sees a generic 502 with no remediation hint. There is also no way to A/B test a new model without a code change.

**Fix direction:** Read `ANTHROPIC_MODEL` from env, default to the current value, validate against an allow-list at startup.

---

## 🟢 Bug 8 — Inconsistent / deprecated `datetime.utcnow()`

**Severity:** Low — works today, deprecated in Python 3.12+.

**Evidence:**
- `backend/app/models/resume.py`: `default=datetime.utcnow`
- `backend/app/routers/resumes.py`: `uploaded_at=datetime.utcnow()`
- `backend/app/routers/health.py`: already uses `datetime.now(timezone.utc)` ✅

**Fix direction:** Replace all `datetime.utcnow` callsites with `datetime.now(timezone.utc)` and store timezone-aware datetimes.

## Suggested sequencing before starting Issue #7

1. **Fix Bug 2** (extraction + new column + migration) — without it the role-template "Generate from template" action has no resume text to pass to Claude.
2. **Fix Bug 1** (frontend/backend contract on the generate endpoint) — option (b) from the fix direction aligns cleanly with template-driven generation.
3. **Fix Bugs 3 & 4** (harden `claude_service`) — otherwise the new feature will look broken in prod despite passing local mocks.
4. **Fix Bugs 5–8** in the same PR or immediately after — they're all small, but each one compounds the next.
5. **Then start the `role_templates` table/migration/CRUD work** on a stable foundation.

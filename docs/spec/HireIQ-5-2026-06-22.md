## Issue Summary

As a recruiter, after generating interview questions I want to see them in a **clean, readable, categorised layout** — Technical / Behavioural / Culture Fit — with each card showing the main question, its follow-up, and an evaluation tip. A loading skeleton should appear during generation, and I must be able to **copy individual questions or the full set** to my clipboard for use during the interview.

---

## Problem Statement

The M2 backend (`/api/generate/`) successfully returns categorised questions with follow-ups and tips, but the frontend renders them as a single green status string (`App.tsx:85` — `{generateResult.message}`). This creates three concrete problems:

1. **Unreadable output** — recruiters cannot actually use the questions during an interview.
2. **Type contract drift** — `frontend/src/App.tsx:12-18` defines `GenerateResult` as the *stub* shape `{message, resume_id, job_title, seniority_level, key_skills[]}`, while the real backend returns `{technical, behavioural, culture_fit: Question[]}`. TypeScript silently accepts both because the shape is widened via `as GenerateResult` (`App.tsx:48`), masking the mismatch.
3. **No loading state** — recruiters see no feedback while the LLM call is in flight; the only signal is the disabled `JobRoleForm` button.

Without this fix the M3 milestone — recruiter-facing question UI — is functionally incomplete.

## Expected Behaviour

1. Recruiter clicks **Generate Questions** → loading skeleton appears immediately (3 category sections × 3 shimmering card placeholders).
2. Backend returns `{technical, behavioural, culture_fit}` → skeleton is replaced by three **collapsible category sections**.
3. Each section is expanded by default and shows a count badge (e.g. `Technical (4)`).
4. Each question card displays, top to bottom:
   - **Main question** (bold, larger)
   - **Follow-up** (blue callout box)
   - **Evaluation tip** (yellow callout box)
   - **📋 Copy** button (per-card; shows "✓ Copied" for 2 s)
5. A **📋 Copy all questions** button at the top copies every question (with category labels) as plain text.
6. Errors render in red; success dismisses on next generation.

## Proposed Solution

### Architecture Overview

```
React <App>
  │
  ├── handleGenerate(roleData)
  │     POST /api/generate/  →  GenerateResponse
  │     (real contract — see API Contract below)
  │
  └── render:
        generating === true  →  <QuestionSkeleton />
        generateResult !== null → <QuestionDisplay result={...} />
        generateError !== null →  red error <p>
```

No backend changes. No new npm dependencies. No router changes. All work is isolated to `frontend/src/`.

### Step 1 — Fix `frontend/src/App.tsx`

Replace the stub type with the real contract, and update the render tree.

```tsx
// frontend/src/App.tsx (relevant diff)
import { useEffect, useState } from 'react'
import { ResumeList } from './components/ResumeList'
import { ResumeUpload } from './components/ResumeUpload'
import { JobRoleForm, JobRoleData } from './components/JobRoleForm'
import { QuestionDisplay } from './components/QuestionDisplay'
import { QuestionSkeleton } from './components/QuestionSkeleton'
import type { GenerateResponse, Question } from './types/generate'

// (stale GenerateResult type DELETED)

function App() {
  const [resumes, setResumes] = useState<Resume[]>([])
  const [activeResumeId, setActiveResumeId] = useState<number | null>(null)
  const [generateResult, setGenerateResult] = useState<GenerateResponse | null>(null)
  const [generateError, setGenerateError] = useState<string | null>(null)
  const [generating, setGenerating] = useState(false)

  // ... existing useEffect + handleUploaded unchanged ...

  const handleGenerate = async (roleData: JobRoleData) => {
    if (!activeResumeId) return
    setGenerating(true)
    setGenerateResult(null)
    setGenerateError(null)
    try {
      const res = await fetch('/api/generate/', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          resume_id: activeResumeId,
          job_title: roleData.jobTitle,
          seniority_level: roleData.seniorityLevel,
          key_skills: roleData.keySkills,
        }),
      })
      const data: GenerateResponse = await res.json()
      if (!res.ok) throw new Error(data.detail ?? `HTTP ${res.status}`)
      setGenerateResult(data)
    } catch (err: unknown) {
      setGenerateError(err instanceof Error ? err.message : 'Generation failed.')
    } finally {
      setGenerating(false)
    }
  }

  return (
    <div style={{ fontFamily: 'sans-serif', padding: '2rem', maxWidth: 960, margin: '0 auto' }}>
      <h1>HireIQ</h1>
      <ResumeUpload onUploaded={handleUploaded} />
      <hr style={{ margin: '2rem 0' }} />
      <JobRoleForm onSubmit={handleGenerate} disabled={!activeResumeId || generating} />
      {!activeResumeId && (
        <p style={{ color: '#888', marginTop: 8 }}>Upload a resume to enable question generation.</p>
      )}
      {generateError && <p style={{ color: 'red' }} role="alert">{generateError}</p>}
      {generating && <QuestionSkeleton />}
      {generateResult && <QuestionDisplay result={generateResult} />}
      <h2>Uploaded Resumes</h2>
      <ResumeList resumes={resumes} />
    </div>
  )
}

export default App
```

**Why this works:**
- Removes the false `GenerateResult` type that was hiding the contract drift.
- The single-step `POST /api/generate/` matches the M2 backend exactly — no second fetch, no duplicate text extraction.
- `role="alert"` on the error message makes the failure announcement accessible to screen readers.

### Step 3 — New Component: `QuestionCard.tsx`

```tsx
// frontend/src/components/QuestionCard.tsx
import { useState } from 'react'
import type { Question } from '../types/generate'

type Props = {
  category: string
  index: number
  question: Question
}

export function QuestionCard({ category, index, question }: Props) {
  const [copied, setCopied] = useState(false)

  async function handleCopy() {
    const text =
      `[${category}] Q${index + 1}: ${question.text}\n` +
      `Follow-up: ${question.follow_up}\n` +
      `What to listen for: ${question.what_to_listen_for}`
    try {
      await navigator.clipboard.writeText(text)
      setCopied(true)
      setTimeout(() => setCopied(false), 2000)
    } catch {
      // Clipboard API unavailable (non-HTTPS / older browser) — fail silently
    }
  }

  return (
    <article
      data-testid="question-card"
      style={{
        border: '1px solid #e5e7eb',
        borderRadius: 8,
        padding: '1rem',
        marginBottom: '1rem',
        background: '#fff',
      }}
    >
      <header style={{ display: 'flex', justifyContent: 'space-between', alignItems: 'flex-start' }}>
        <p style={{ margin: 0, fontWeight: 600, fontSize: '1.05rem' }}>
          Q{index + 1}. {question.text}
        </p>
        <button
          type="button"
          onClick={handleCopy}
          aria-label={`Copy question ${index + 1}`}
          style={{ marginLeft: 12, flexShrink: 0 }}
        >
          {copied ? '✓ Copied' : '📋 Copy'}
        </button>
      </header>

      <div
        style={{
          marginTop: 12,
          padding: '0.5rem 0.75rem',
          background: '#eff6ff',
          borderLeft: '3px solid #3b82f6',
          borderRadius: 4,
        }}
      >
        <strong>Follow-up:</strong> {question.follow_up}
      </div>

      <div
        style={{
          marginTop: 8,
          padding: '0.5rem 0.75rem',
          background: '#fef3c7',
          borderLeft: '3px solid #f59e0b',
          borderRadius: 4,
        }}
      >
        <strong>What to listen for:</strong> {question.what_to_listen_for}
      </div>
    </article>
  )
}
```

**Why this shape:**
- Uses semantic `<article>` + `<header>` (per `CODE_REVIEW.md` accessibility standards).
- Per-card `aria-label` so screen readers announce "Copy question 1" instead of just "Copy".
- Visual hierarchy: blue callout = conversational cue, yellow callout = evaluation cue.
- Copy text includes category + index so a pasted transcript stays coherent.

### Step 4 — New Component: `QuestionSkeleton.tsx`

```tsx
// frontend/src/components/QuestionSkeleton.tsx
const CATEGORIES = ['Technical', 'Behavioural', 'Culture Fit'] as const
const CARDS_PER_CATEGORY = 3

export function QuestionSkeleton() {
  return (
    <div
      role="status"
      aria-label="Generating questions"
      aria-live="polite"
      style={{ marginTop: '1.5rem' }}
    >
      {CATEGORIES.map((cat) => (
        <section key={cat} style={{ marginBottom: '1.5rem' }}>
          <h3 style={{ color: '#6b7280' }}>{cat}</h3>
          {Array.from({ length: CARDS_PER_CATEGORY }).map((_, i) => (
            <div
              key={i}
              style={{
                height: 96,
                marginBottom: 12,
                borderRadius: 8,
                background:
                  'linear-gradient(90deg, #f3f4f6 0%, #e5e7eb 50%, #f3f4f6 100%)',
                backgroundSize: '200% 100%',
                animation: 'shimmer 1.4s ease-in-out infinite',
              }}
            />
          ))}
        </section>
      ))}
      {/* Shimmer keyframes — appended via a <style> tag to avoid a global CSS file */}
      <style>{`
        @keyframes shimmer {
          0%   { background-position: 200% 0; }
          100% { background-position: -200% 0; }
        }
      `}</style>
    </div>
  )
}
```

**Why this shape:**
- `role="status"` + `aria-live="polite"` announces the loading state to assistive tech (matches `UNIT_TESTING.md` a11y expectations).
- Three categories × three placeholders mirrors the most common LLM response (≈ 9 questions total), so the layout doesn't reflow when data arrives.
- Shimmer is achieved via inline gradient + CSS keyframes; no animation library, no CSS file edit.

### Step 5 — New Component: `QuestionDisplay.tsx`

```tsx
// frontend/src/components/QuestionDisplay.tsx
import { useState } from 'react'
import { QuestionCard } from './QuestionCard'
import { CATEGORY_LABELS, type Category, type GenerateResponse } from '../types/generate'

type Props = { result: GenerateResponse }

const CATEGORY_ORDER: Category[] = ['technical', 'behavioural', 'culture_fit']

export function QuestionDisplay({ result }: Props) {
  const [collapsed, setCollapsed] = useState<Record<Category, boolean>>({
    technical: false,
    behavioural: false,
    culture_fit: false,
  })
  const [copiedAll, setCopiedAll] = useState(false)

  function toggle(key: Category) {
    setCollapsed((prev) => ({ ...prev, [key]: !prev[key] }))
  }

  async function handleCopyAll() {
    const sections = CATEGORY_ORDER.flatMap((key) => {
      const label = CATEGORY_LABELS[key]
      return result[key].map(
        (q, i) =>
          `[${label}] Q${i + 1}: ${q.text}\n` +
          `  Follow-up: ${q.follow_up}\n` +
          `  What to listen for: ${q.what_to_listen_for}`,
      )
    })
    try {
      await navigator.clipboard.writeText(sections.join('\n\n'))
      setCopiedAll(true)
      setTimeout(() => setCopiedAll(false), 2000)
    } catch {
      // Non-HTTPS / unsupported — fail silently
    }
  }

  return (
    <section style={{ marginTop: '1.5rem' }}>
      <header style={{ display: 'flex', justifyContent: 'space-between', alignItems: 'center' }}>
        <h2 style={{ margin: 0 }}>Generated Questions</h2>
        <button type="button" onClick={handleCopyAll} aria-label="Copy all questions">
          {copiedAll ? '✓ Copied all' : '📋 Copy all questions'}
        </button>
      </header>

      {CATEGORY_ORDER.map((key) => {
        const questions = result[key]
        const isCollapsed = collapsed[key]
        return (
          <section key={key} style={{ marginTop: '1.25rem' }}>
            <button
              type="button"
              onClick={() => toggle(key)}
              aria-expanded={!isCollapsed}
              aria-controls={`category-${key}`}
              style={{
                background: 'none',
                border: 'none',
                padding: 0,
                fontSize: '1.1rem',
                fontWeight: 600,
                cursor: 'pointer',
                color: '#111827',
              }}
            >
              {CATEGORY_LABELS[key]} ({questions.length}) {isCollapsed ? '▸' : '▾'}
            </button>
            {!isCollapsed && (
              <div id={`category-${key}`} style={{ marginTop: 8 }}>
                {questions.length === 0 ? (
                  <p style={{ color: '#888', fontStyle: 'italic' }}>No questions in this category.</p>
                ) : (
                  questions.map((q, i) => (
                    <QuestionCard
                      key={`${key}-${i}`}
                      category={CATEGORY_LABELS[key]}
                      index={i}
                      question={q}
                    />
                  ))
                )}
              </div>
            )}
          </section>
        )
      })}
    </section>
  )
}
```

**Why this shape:**
- `aria-expanded` + `aria-controls` is the WAI-ARIA disclosure pattern — keyboard-navigable, screen-reader-friendly.
- Per-category collapse state is local; recruiters can hide categories they don't need during the interview without losing context.
- "Copy all" produces a recruiter-ready transcript (category label, indexed questions, indented follow-up/tip) suitable for pasting into a doc.

## Edge Cases & Risks

| Scenario | Mitigation |
|---|---|
| Backend returns empty arrays (e.g. `technical: []`) | Per-category fallback message: *"No questions in this category."* (line 92 of `QuestionDisplay.tsx`) |
| One category missing from response entirely | Optional chaining + `?? []` in CATEGORY_ORDER.map to avoid `TypeError` |
| LLM returns very long question text | CSS `word-wrap: break-word` (browser default) on `<p>`; no truncation — recruiters need the full text |
| `navigator.clipboard` blocked (non-HTTPS, older browser, permissions denied) | `try/catch` around `writeText` — failure is silent; copy button still renders for affordance |
| User clicks "Generate" twice rapidly | `disabled` on `JobRoleForm` while `generating === true` (already in place) |
| Network error during generation | `generateError` state renders red `<p role="alert">`; previous result is cleared (`setGenerateResult(null)`) so skeleton shows on retry |
| `tsc --noEmit` silently widens `unknown` | Use `data: GenerateResponse` (not `as GenerateResponse`) so the compiler enforces the contract on the response |
| Animation reduces-motion users | Add `@media (prefers-reduced-motion: reduce) { @keyframes shimmer { from, to { background-position: 0 0; } } }` inside the `<style>` tag |
| Backend adds a new category in M4 | `CATEGORY_ORDER` is the iteration source — add the key to the union + array in one place |

## Issue Summary

Build a rich question-display UI on the React frontend that renders AI-generated interview questions, grouped into collapsible category sections (Technical, Behavioural, Culture Fit). Each question card shows the main question text, a follow-up probe, and a recruiter evaluation tip. A loading skeleton is shown while generation is in progress. Individual questions and the entire question set can be copied to the clipboard.

This issue also repairs a pre-existing integration gap: `App.tsx` currently holds a stale placeholder `GenerateResult` type and sends `resume_id` to `POST /api/generate`, whereas the backend expects `resume_text`. Both must be corrected as part of this work.

---

## Problem Statement

After Milestone 2 implemented `POST /api/generate` (Issue #4), the frontend has no meaningful UI to render the structured response. The current `App.tsx` renders only a plain-text success message and uses an outdated type definition that doesn't match the actual API contract:

- `GenerateResult` in `App.tsx` models a stub response (`{ message, resume_id, job_title, seniority_level, key_skills }`) — the real API returns `{ technical, behavioural, culture_fit }` where each entry is `{ text, follow_up, what_to_listen_for }`.
- The `handleGenerate` function posts `resume_id` to `POST /api/generate`, but the backend route accepts `resume_text` (the raw extracted content of the resume file). This mismatch causes all generate requests to fail with a 422 error in production.
- No loading state indicator is shown while the Claude API is in flight.
- No copy-to-clipboard functionality exists.

---

## Current Behavior

1. Recruiter uploads a resume and fills in the Job Role form.
2. "Generate Questions" is clicked → `App.tsx` POSTs `{ resume_id, job_title, seniority_level, key_skills }` to `/api/generate/`.
3. The backend (which expects `resume_text`) returns HTTP 422.
4. Even if the request were valid, the UI shows only `<p style={{ color: 'green' }}>{generateResult.message}</p>` — no structured question output.

---

## Expected Behavior

1. When the recruiter clicks "Generate Questions" the UI shows a multi-row loading skeleton.
2. On success the skeleton is replaced by three collapsible sections: **Technical**, **Behavioural**, **Culture Fit**.
3. Each section header shows the category name and question count and toggles expand/collapse.
4. Each question card shows:
   - The main question text (bold / prominent).
   - A "Follow-up" field labelled appropriately.
   - An "Evaluation tip" field (what to listen for).
   - A Copy button that copies that card's question + follow-up + tip to the clipboard.
5. A "Copy all questions" button at the top of the results copies all questions across all categories as formatted plain text.
6. The generate request is sent with the correct payload (extracted resume text is fetched from the backend before calling `/api/generate`).

## Root Cause Analysis

### Integration gap — `resume_id` vs `resume_text`

The Resume model (`backend/app/models/resume.py`) stores the file at `uploads/resumes/{stored_filename}` but does **not** persist extracted text. The backend `POST /api/generate` requires `resume_text` (a string).

Options considered:

| Option | Pros | Cons |
|--------|------|------|
| **A** — Add `GET /api/resumes/{id}/text` backend endpoint that extracts and returns text | Clean separation of concerns; text extraction done server-side using existing `pdfplumber` dependency | Two round-trips from frontend; text not cached |
| **B** — Modify `POST /api/generate` to accept `resume_id` (backend reads file + extracts text internally) | Single API call from frontend; simpler frontend logic | Couples generation service to file system |
| **C** — Persist extracted text at upload time (new `resume_text` column) | Fastest at generate time | Requires migration; changes upload flow (Issue #2 scope) |

**Recommendation:** Option A. Add `GET /api/resumes/{id}/text` that returns `{ resume_text: string }` using `pdfplumber` (already in `requirements.txt`). The frontend fetches this before POSTing to `/api/generate`. This preserves the existing API contract and avoids schema changes.

### Frontend stale type

`App.tsx`'s `GenerateResult` type was written during the stub phase and must be replaced with the actual API shape. The real response matches:

```ts

  text: string
  follow_up: string
  what_to_listen_for: string
}

type GenerateResult = {
  technical: Question[]
  behavioural: Question[]
  culture_fit: Question[]
}
```

### Missing UI components

No `QuestionDisplay`, `QuestionCard`, or `QuestionSkeleton` components exist. All must be created.

### Step 1 — New backend endpoint: `GET /api/resumes/{id}/text`

Add to `backend/app/routers/resumes.py`:

```python
import pdfplumber
import io

@router.get("/{resume_id}/text")
def get_resume_text(resume_id: int, db: Session = Depends(get_db)):
    """Extract and return the raw text from a stored resume file."""
    resume = db.query(Resume).filter(Resume.id == resume_id).first()
    if not resume:
        raise HTTPException(status_code=404, detail="Resume not found.")

    file_path = os.path.join(UPLOAD_DIR, resume.stored_filename)
    if not os.path.exists(file_path):
        raise HTTPException(status_code=404, detail="Resume file not found on disk.")

    try:
        with pdfplumber.open(file_path) as pdf:
            text = "\n".join(
                page.extract_text() or "" for page in pdf.pages
            ).strip()
    except Exception as exc:
        raise HTTPException(
            status_code=422,
            detail=f"Could not extract text from resume: {exc}"
        )

    if not text:
        raise HTTPException(
            status_code=422,
            detail="No extractable text found in this resume. Please upload a text-based PDF."
        )

    return {"resume_text": text}
```

> **Note:** DOCX support can be added via `python-docx` in a follow-up. For M2, only PDF is fully supported.

```tsx
// Updated types

  text: string
  follow_up: string

}

type GenerateResult = {
  technical: Question[]
  behavioural: Question[]
  culture_fit: Question[]
}

// Updated handleGenerate
const handleGenerate = async (roleData: JobRoleData) => {
  if (!activeResumeId) return
  setGenerating(true)
  setGenerateResult(null)
  setGenerateError(null)

  try {
    // Step 1: fetch extracted resume text
    const textRes = await fetch(`/api/resumes/${activeResumeId}/text`)
    const textData = await textRes.json()
    if (!textRes.ok) throw new Error(textData.detail ?? `Could not read resume text`)

    // Step 2: generate questions
    const res = await fetch('/api/generate/', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        resume_text: textData.resume_text,
        job_title: roleData.jobTitle,
        seniority_level: roleData.seniorityLevel,
        key_skills: roleData.keySkills,
      }),
    })
    const data = await res.json()
    if (!res.ok) throw new Error(data.detail ?? `HTTP ${res.status}`)
    setGenerateResult(data as GenerateResult)
  } catch (err: unknown) {
    setGenerateError(err instanceof Error ? err.message : 'Generation failed.')
  } finally {
    setGenerating(false)
  }
}
```

### Step 4 — `QuestionDisplay.tsx`

**File:** `frontend/src/components/QuestionDisplay.tsx`

```tsx
import { useState } from 'react'
import { QuestionCard, Question } from './QuestionCard'

type QuestionSet = {
  technical: Question[]
  behavioural: Question[]
  culture_fit: Question[]
}

type Props = {
  questions: QuestionSet
}

type CategoryKey = keyof QuestionSet

const CATEGORY_LABELS: Record<CategoryKey, string> = {
  technical: 'Technical',
  behavioural: 'Behavioural',
  culture_fit: 'Culture Fit',
}

const CATEGORY_COLOURS: Record<CategoryKey, string> = {
  technical: '#6366f1',
  behavioural: '#0891b2',
  culture_fit: '#16a34a',
}

function buildAllText(questions: QuestionSet): string {
  return (Object.entries(CATEGORY_LABELS) as [CategoryKey, string][])
    .map(([key, label]) => {
      const section = questions[key]
        .map(
          (q, i) =>
            `${i + 1}. ${q.text}\n   Follow-up: ${q.follow_up}\n   Tip: ${q.what_to_listen_for}`
        )
        .join('\n\n')
      return `=== ${label} ===\n${section}`
    })
    .join('\n\n')
}

export function QuestionDisplay({ questions }: Props) {
  const [openSections, setOpenSections] = useState<Record<CategoryKey, boolean>>({
    technical: true,
    behavioural: true,
    culture_fit: true,
  })
  const [allCopied, setAllCopied] = useState(false)

  const toggleSection = (key: CategoryKey) => {
    setOpenSections((prev) => ({ ...prev, [key]: !prev[key] }))
  }

  const handleCopyAll = async () => {
    await navigator.clipboard.writeText(buildAllText(questions))
    setAllCopied(true)
    setTimeout(() => setAllCopied(false), 2000)
  }

  return (
    <div style={{ marginTop: '2rem' }}>
      <div style={{ display: 'flex', justifyContent: 'space-between', alignItems: 'center', marginBottom: '1rem' }}>
        <h2 style={{ margin: 0 }}>Generated Questions</h2>
        <button
          onClick={handleCopyAll}
          aria-label="Copy all questions"
          style={{
            border: '1px solid #cbd5e1',
            borderRadius: 6,
            padding: '6px 14px',
            background: allCopied ? '#dcfce7' : '#f8fafc',
            cursor: 'pointer',
            fontSize: 13,
            color: allCopied ? '#16a34a' : '#334155',
          }}
        >
          {allCopied ? '✓ All copied!' : '📋 Copy all questions'}
        </button>
      </div>

      {(Object.entries(CATEGORY_LABELS) as [CategoryKey, string][]).map(([key, label]) => {
        const colour = CATEGORY_COLOURS[key]
        const isOpen = openSections[key]
        const qs = questions[key]

        return (
          <div key={key} style={{ marginBottom: '1.5rem' }}>
            <button
              onClick={() => toggleSection(key)}
              aria-expanded={isOpen}
              style={{
                width: '100%',
                textAlign: 'left',
                background: colour,
                color: '#fff',
                border: 'none',
                borderRadius: isOpen ? '8px 8px 0 0' : 8,
                padding: '0.75rem 1rem',
                cursor: 'pointer',
                display: 'flex',
                justifyContent: 'space-between',
                alignItems: 'center',
                fontWeight: 700,
                fontSize: 15,
              }}
            >
              <span>{label}</span>
              <span style={{ fontSize: 12, opacity: 0.85 }}>
                {qs.length} question{qs.length !== 1 ? 's' : ''} {isOpen ? '▲' : '▼'}
              </span>
            </button>

            {isOpen && (
              <div
                style={{
                  border: `1px solid ${colour}`,
                  borderTop: 'none',
                  borderRadius: '0 0 8px 8px',
                  padding: '1rem',
                  background: '#fafafa',
                }}
              >
                {qs.map((q, i) => (
                  <QuestionCard key={i} question={q} index={i} />
                ))}
              </div>
            )}
          </div>
        )
      })}
    </div>
  )
}
```

## Edge Cases & Risks

| Scenario | Mitigation |
|----------|-----------|
| PDF has no extractable text (scanned image) | New endpoint returns 422 with message "No extractable text found…"; `App.tsx` displays as `generateError` |
| DOCX resume uploaded (not PDF) | `pdfplumber` will fail; catch exception → 422; add `python-docx` support in a follow-up |
| `navigator.clipboard.writeText` unavailable (non-HTTPS or older browser) | Wrap in `try/catch`; if it throws, show a brief error tooltip on the copy button |
| Category has 0 questions (API edge case) | `QuestionDisplay` renders the section with count 0 and an empty body; no crash |
| Very long question text overflowing the card | CSS `word-break: break-word` on `<p>` elements inside `QuestionCard` |
| Network error fetching resume text before generate | `handleGenerate` catches the error and sets `generateError`; skeleton is not shown |
| User clicks "Generate Questions" multiple times rapidly | `setGenerating(true)` at the start disables the button; double-submit impossible |
| Clipboard API requires user gesture | The copy button `onClick` is a direct user gesture — no async wrapper needed |
| `App.test.tsx` existing tests rely on stale mock shape | Update the MSW handler for `POST /api/generate/` to return the real `{ technical, behavioural, culture_fit }` shape; update any assertions referencing `generateResult.message` |

## Notes

- **No CSS framework**: The project uses inline styles throughout. All new components follow the same pattern — no new external dependencies required.
- **Clipboard API**: Available in all modern browsers over HTTPS. For local dev (HTTP), Vite's dev server must be served over HTTPS or the clipboard write will silently fail — handle gracefully.
- **Accessibility**: All interactive controls use semantic `<button>` elements with `aria-label`. The skeleton has `role="status"` and `aria-label="Generating questions…"` for screen reader compatibility. Collapsible section buttons use `aria-expanded`.
- **DOCX support**: The `pdfplumber`-only implementation covers the primary resume format. Adding `python-docx` for DOCX files is out of scope for this issue but straightforward to add.
- **Copy format**: Plain text with `===` section headers is the most interoperable format for pasting into email, notes, or ATS tools. Rich text / Markdown copy can be offered as a follow-up enhancement.
- **Persistence**: Generated question sets are not persisted to the database (consistent with Issue #4's design). If history/replay is required, add a `question_sets` table in a future milestone.

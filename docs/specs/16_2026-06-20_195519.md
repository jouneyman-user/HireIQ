### Step 1 — New component: `frontend/src/components/AppFooter.tsx`

```tsx
/**
 * AppFooter — global, branded footer for the HireIQ web app.
 *
 * Renders the HireIQ wordmark, a short tagline, and a copyright line
 * with the *current* calendar year (computed at runtime, never hard-coded).
 *
 * Themeing is inherited from the CSS custom properties defined in
 * `index.css` (`--text`, `--text-h`, `--border`, `--accent`), so the
 * footer automatically adapts to light / dark mode.
 */
export const APP_NAME = 'HireIQ'
export const APP_TAGLINE = 'AI-powered interview prep for modern recruiting teams.'
export const COPYRIGHT_NOTICE = `© ${new Date().getFullYear()} ${APP_NAME}. All rights reserved.`

export function AppFooter() {
  return (
    <footer
      role="contentinfo"
      aria-label={`${APP_NAME} footer`}
      style={{
        marginTop: '4rem',
        paddingTop: '1.5rem',
        paddingBottom: '1.5rem',
        borderTop: '1px solid var(--border)',
        textAlign: 'center',
        color: 'var(--text)',
        fontSize: 14,
        lineHeight: 1.5,
      }}
    >
      <div
        style={{
          fontFamily: 'var(--heading)',
          fontWeight: 600,
          color: 'var(--text-h)',
          fontSize: 18,
          letterSpacing: '-0.2px',
          marginBottom: 4,
        }}
      >
        {APP_NAME}
      </div>
      <div style={{ marginBottom: 8 }}>{APP_TAGLINE}</div>
      <div style={{ fontSize: 12, opacity: 0.85 }}>{COPYRIGHT_NOTICE}</div>
    </footer>
  )
}

export default AppFooter
```

**Key design notes**

- Three exported constants (`APP_NAME`, `APP_TAGLINE`, `COPYRIGHT_NOTICE`) so branding copy lives in one place. Editing the tagline or product name is a one-line change.
- `COPYRIGHT_NOTICE` uses a **template literal evaluated at module load**. This means the year is captured once when the bundle is parsed by the browser, which for a normal SPA session is effectively "current year" (the user is unlikely to keep a tab open across New Year's Eve, and even then the difference is one calendar year). If true midnight-rollover precision is ever required, swap the template literal for an inline `{new Date().getFullYear()}` inside the JSX.
- All spacing, colours, and typography come from the existing CSS custom properties — no new CSS file and no Tailwind / CSS-in-JS dependency is introduced.
- `role="contentinfo"` plus `aria-label` makes the footer discoverable to assistive tech without needing a visible heading inside it (the visible wordmark acts as the visual anchor).

## Notes & Assumptions

- **Assumption A1 — Year handling.** The ticket title says "current year" and the ticket body says "add year as 2027". This spec implements dynamic current year (`new Date().getFullYear()`). Reviewer can flip to a hard-coded `2027` with a single-line edit; the constant `COPYRIGHT_NOTICE` is exported precisely so this is a one-touch override.
- **Assumption A2 — Tagline.** No brand book or product brief exists in the repository. The tagline **"AI-powered interview prep for modern recruiting teams."** is invented for this spec. It is exported as `APP_TAGLINE` for easy override.
- **Assumption A3 — No external links.** The ticket does not request Privacy / Terms / Contact links, and no such pages exist in the repo. Adding them is a separate, follow-up issue.
- **Assumption A4 — Single-route SPA.** The footer is mounted inside `<App />`. Today the app has a single route, so the footer appears on every page. When React Router is introduced, the footer should be hoisted to the router layout (one-line refactor). This is intentionally not done now to keep this issue's blast radius minimal.
- **No CSS framework, no new dependencies.** The project uses inline styles throughout. The new component follows the same pattern (see `ResumeList.tsx` for the established style). Zero `package.json` changes.
- **Accessibility.** `<footer>` is a sectioning content element with implicit `role="contentinfo"`. Adding an explicit `role="contentinfo"` and `aria-label="HireIQ footer"` makes the landmark discoverable in assistive tech and gives it a stable, screen-reader-friendly name.
- **Theming.** Re-using `var(--text)`, `var(--text-h)`, and `var(--border)` means the footer picks up the dark-mode palette automatically because `index.css` already redefines those variables inside `@media (prefers-color-scheme: dark)`. No conditional styles, no JS theme switcher needed.
- **Module-load evaluation of `COPYRIGHT_NOTICE`.** The template literal `\`© ${new Date().getFullYear()} ${APP_NAME}. All rights reserved.\`` is evaluated once when the module is first imported. For a long-lived tab this can be off by one calendar year at the stroke of midnight on 1 Jan. If true rollover precision is later required, change the constant to a function or inline the expression in JSX. Tests cover both behaviours.
